# AI Exit Guard

AI Exit Guard — приложение для строки меню macOS. Оно направляет Claude, ChatGPT и Google Antigravity через выбранные прокси и показывает статус каждого сервиса.

[Опубликованные сборки для macOS и Windows](https://github.com/Waizor1/ai-exit-guard/releases). Описание ниже относится к исходникам в этой ветке.

Требуется macOS 13 или новее. Откройте DMG и запустите `AI Exit Guard.pkg`. Установщик запросит права администратора для системного помощника. Бета-сборка имеет локальную подпись ad hoc и не прошла нотарификацию Apple, поэтому Gatekeeper может остановить установку.

Подключите общий HTTP(S)- или SOCKS5-прокси. В списке выберите Claude, ChatGPT или Antigravity. Переключатель «Индивидуальный» позволяет назначить свой прокси выбранному сервису. «Общий» возвращает его на основной выход. Реквизиты хранятся в Связке ключей.

### Как пользоваться

Вставьте адрес прокси и нажмите **Подключить**. При первом подключении Guard проверит выход и настроит локальный маршрут для известных адресов ИИ. На Mac это делает помощник из PKG. На Windows запустите **AI Exit Guard.exe** из распакованного ZIP. Windows может запросить подтверждение при изменении системного маршрута. Сохранённый пароль защищён Связкой ключей на Mac или DPAPI для текущего пользователя Windows.

По умолчанию новое подключение работает в режиме **Только прокси**. Диагностическая проверка IP в этом режиме не прерывает сеансы. Если включить **Килл-свитч**, подтверждённый высокий риск или смена закреплённого адреса закрывает туннели соответствующего сервиса. Временный сбой проверки позволяет использовать оставшееся время предыдущего разрешения. При истечении срока Guard ждёт свежей оценки. Восстановление соединения открывает путь для нового запроса. Уже оборванный ответ модели может потребоваться повторить в клиенте.

Откройте Claude, ChatGPT или Antigravity как обычно. Назначения выбираются по имени сервера. MCP, SSH, Git и другие инструменты могут использовать свои обычные маршруты. Для обновления настроек ранее запущенного с ограничениями агента завершите его старый процесс в удобный момент. Guard удаляет из настроек T3 собственные старые программы запуска и значения прокси. Параметры сторонних прокси сохраняются.

### Публичные MCP на Mac

Guard читает адреса HTTPS-серверов из конфигураций Codex, Claude, Gemini, Antigravity и OpenCode. Для автоматической проверки подходят точные имена публичных MCP из каталога, включённого в сборку. Разработчик обновляет этот снимок из официального реестра MCP. Локальные имена, частные адреса, правила корпоративного DNS и записи файла hosts исключаются.

Если два последовательных соединения с публичным MCP срываются до установления TLS, Guard сверяет адрес через зашифрованный DNS Cloudflare и проверяет сертификат сервера на полученном IP. При успешной проверке в macOS появляется временное правило для этого MCP. Оно действует до трёх минут. В разделе «Настройки» можно увидеть активные имена и снять правила до перезапуска Guard. Пауза прокси, смена сети и выход из приложения также снимают временные правила.

Эта функция рассчитана на клиентов системного DNS macOS. Авторизацию, доступность удалённого приложения и ответы HTTP проверяет сам клиент MCP.

### Что покрывает маршрут

Встроенный помощник направляет известные имена серверов ИИ из системного DNS в локальный TLS-вход. Запросы HTTPS с этими именами идут через выбранный прокси. Guard не расшифровывает соединение. Приложения с поддержкой системного PAC на Mac также используют правила для поддоменов. Собственный DNS, прямой IP, вложенный VPN и UDP требуют отдельной проверки. Результат диагностики показывает адрес конкретного проверенного запроса.

Дополнительный фильтр ProxyBridge, если он установлен, обрабатывает известные HTTPS-домены. Для Antigravity и T3 у фильтра есть узкие правила к общим адресам входа Google. Остальные приложения сохраняют свой маршрут к ним. Доступ к аккаунту и квоты определяет провайдер.

**Отключить прокси** снимает маршруты, которые Guard добавил при подключении. В правилах предыдущих версий могли остаться явно включённые системные записи. Их можно снять в настройках Guard. В режиме с килл-свитчем системное правило может оставаться включённым после выхода из программы.

## Локальная сборка

Понадобятся Mac, инструменты командной строки Xcode, Python 3 и Go 1.26.3 или совместимая более новая версия. Запустите сборку из корня проекта.

```sh
./build.sh
```

Скрипт собирает приложение и помощник для Apple Silicon и Intel. В папке `dist` появится образ `AI Exit Guard.dmg` с установщиком. Локальная сборка использует подпись ad hoc. Для подписанной и нотарифицированной сборки предусмотрен режим `./build.sh --release` с переменными `DEVELOPER_ID_APPLICATION`, `DEVELOPER_ID_INSTALLER` и `NOTARY_KEYCHAIN_PROFILE`.

## Проверка

```sh
go test -race ./...
python3 tests/check_red_relay.py
```

Вторая команда на macOS проверяет, что красный результат закрывает уже открытое соединение, новые подключения получают отказ, а полная зелёная проверка восстанавливает доступ. Тест использует локальный сервер.

Настройка прокси, разрешения macOS и значения статусов описаны в [инструкции пользователя](Инструкция.txt).


### Обновления macOS с сохранением разрешений

Первую установку канала Developer ID и изменения системных служб выпускайте через `./build.sh --release`. Для обновления только приложения используйте `./build.sh --app-update` с теми же Developer ID Application и профилем нотарификации. Этот режим создаёт `dist/AI Exit Guard App Update.zip`. Распакуйте приложение и замените предыдущую копию в том же каталоге с правом записи. Если изменились системные правила, интерфейс XPC, демон входящих соединений или их установка, выпустите полный PKG.

Установленный через этот канал помощник проверяет идентификатор Guard, цепочку Developer ID Application и команду разработчика. Связка ключей использует идентичность подписи приложения. При первом переходе с ad hoc macOS может запросить доступ к сохранённому прокси. Локальные бета-сборки по-прежнему требуют совпадения точной подписи с установленным помощником.


Для личного Mac без Developer ID предусмотрены `./build.sh --local-install` и `./build.sh --local-update`. Обе команды требуют один и тот же локальный сертификат подписи кода (`GUARD_LOCAL_CERT_SHA1`) и путь к его связке ключей (`GUARD_LOCAL_KEYCHAIN`). Первый режим создаёт отдельный DMG для перехода с беты, второй — ZIP приложения для обновлений интерфейса. Личный ключ остаётся у владельца. Этот канал не проходит нотарификацию Apple.
